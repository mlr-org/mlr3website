Shrink stored models with butcher

Use a callback to remove training data, calls, and environments from models stored during resampling and tuning.

Author

Marc Becker

Published

November 5, 2026

On this page

  • Scope
  • Butcher a single model
  • Resample callback
  • Tuning
  • Conclusion

Scope

Fitted model objects in R often carry more than they need for prediction. A glm object keeps the training data, the fitted values, the residuals, and the environment of its formula. That is fine for a single model. It adds up when resample() or tune() keep one model per resampling iteration with store_models = TRUE.

The butcher package from the tidymodels ecosystem removes these components while keeping the model usable for prediction. This post shows how to apply it to a single learner and how to wrap it in a callback so that every model stored by mlr3 and mlr3tuning gets shrunk right after training.

library(mlr3)
library(mlr3learners)
library(mlr3tuning)
library(mlr3misc)
library(butcher)

We measure the size of an object by serializing it. This is the number of bytes the object needs on disk or when it is sent to a parallel worker.

serialized_size = function(x) {
  round(length(serialize(x, connection = NULL)) / 1024^2, digits = 2L)
}

Butcher a single model

We train a logistic regression on the spam task with 4601 emails and 57 features.

task = tsk("spam")
learner = lrn("classif.log_reg", predict_type = "prob")
learner$train(task)

serialized_size(learner$model)
[1] 4.44

The model needs about 4.4 MB. The function weigh() lists the components of the model object sorted by size in MB.

weigh(learner$model)
# A tibble: 101 × 2

 7 y                 0.333 
 8 effects           0.0773

10 family.dev.resids 0.0440
# ℹ 91 more rows

The QR decomposition is the largest component. The residuals, fitted values, linear predictors, weights, and the response each take another 0.33 MB. Prediction needs only a fraction of this.

We predict on the task, butcher the model, and write it back into the learner.

prediction = learner$predict(task)
learner$model = butcher(learner$model)

serialized_size(learner$model)
[1] 2.34

The model shrank to roughly half its size. The predictions of the butchered model are identical to the original predictions.

all.equal(prediction, learner$predict(task))
[1] TRUE

The function butcher() only removes components that the predict() method of the model class does not use. It keeps the QR decomposition because predict.glm() needs it to compute standard errors.

Warning

A butchered model has lost information. Functions such as summary(), residuals(), or fitted() may fail or return wrong results on it. Only butcher models that you need for prediction.

Resample callback

We now want to shrink every model that resample() stores. Callbacks run code at specific stages of the resampling loop. We create a resample callback with mlr3::callback_resample(). The stage on_resample_end runs after the learner has been trained and has made its predictions. The context object gives access to the learner of the current iteration.

callback = callback_resample("butcher",
  on_resample_end = function(callback, context) {
    context$learner$model = butcher::butcher(context$learner$model)
  }
)

We call butcher() with the package prefix because the callback may run on a parallel worker on which butcher is not attached.

We run a 5-fold cross-validation twice on the same splits, once without and once with the callback.

resampling = rsmp("cv", folds = 5L)
resampling$instantiate(task)

rr = resample(task, learner, resampling, store_models = TRUE)
rr_butchered = resample(task, learner, resampling, store_models = TRUE, callbacks = callback)

We compare the size of the stored models.

serialized_size(map(rr$learners, "model"))
[1] 19.19
serialized_size(map(rr_butchered$learners, "model"))
[1] 10.4

The five butchered models need about 9 MB less. The callback only touches the stored models, so the performance estimate does not change.

rr$aggregate(msr("classif.auc"))
classif.auc 
   0.971403 
rr_butchered$aggregate(msr("classif.auc"))
classif.auc 
   0.971403

The stored learners still predict new data.

rr_butchered$learners[[1L]]$predict(task)

Tuning

Tuning with store_models = TRUE stores one model per resampling iteration and hyperparameter configuration. Tuning instances take tuning callbacks, which can include the resample stages. We create one with mlr3tuning::callback_batch_tuning().

callback_tuning = callback_batch_tuning("butcher",
  on_resample_end = function(callback, context) {
    context$learner$model = butcher::butcher(context$learner$model)
  }
)

We tune the complexity parameter of a decision tree with 20 random configurations and a 3-fold cross-validation.

learner_rpart = lrn("classif.rpart", cp = to_tune(1e-4, 1e-1, logscale = TRUE))

instance = tune(
  tuner = tnr("random_search"),
  task = task,
  learner = learner_rpart,
  resampling = rsmp("cv", folds = 3L),
  term_evals = 20L,
  store_models = TRUE,
  callbacks = callback_tuning
)

The archive contains a benchmark result with the 60 butchered models.

models = map(instance$archive$benchmark_result$resample_results$resample_result, function(rr) {
  map(rr$learners, "model")
})

serialized_size(models)
[1] 2.68

Conclusion

The butcher package removes data, calls, and environments that a model does not need for prediction. Wrapped in a callback, it shrinks every model that resample(), benchmark(), or tune() stores. The stored results take less memory and are faster to save to disk and to transfer from parallel workers. How much it saves depends on the model class. For model classes without a butcher method, butcher() returns the model unchanged. You can check which classes are supported in the butcher documentation.

# Conclusion

The `butcher` package removes data, calls, and environments that a model does not need for prediction.
Wrapped in a callback, it shrinks every model that `resample()`, `benchmark()`, or `tune()` stores.
The stored results take less memory and are faster to save to disk and to transfer from parallel workers.
How much it saves depends on the model class.
For model classes without a `butcher` method, `butcher()` returns the model unchanged.
You can check which classes are supported in the [butcher documentation](https://butcher.tidymodels.org/articles/available-axe-methods.html).
